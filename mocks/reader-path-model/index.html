Reader path model: Stratos home page — a sketch of an idea, made by hand

What this is

This is a sketch of an idea: a model of the paths that a person who uses a screen reader takes through one page. A box is a component: a control, a title, or a message box. At each box the model holds what a screen reader gets there: the role, the accessible name, the description and the state. The paths are the ways to move over the same boxes: reading order, Tab order, headings, landmarks, actions with their results, and messages that come in time.

Each box shows what the HTML gives now beside the goal. A goal has a source: a WCAG 2.2 success criterion with its level (A, AA or AAA), or "our rule": a person who uses a screen reader gets the same information as a sighted user. The aim is to see the gaps before anyone listens with a screen reader. The model is meant to be generated from an application, filled in, reviewed in a diagram like this one, and then used to change the HTML.

This page is not a tool, and it is not an evaluation. It was made by hand from the source code of the home page of Stratos, the open source web console for Cloud Foundry, on a development branch in November 2026. Nothing was run. Accessible names are worked out by the W3C name rules; they are not measured in a browser. The criterion and level of each gap are one person's reading. Color contrast has its goals but no values: it is not measured yet. Some parts were not read and say so. Endpoint and application names are examples.

How to use it: choose a path, choose a goal level, drill down, and select a box to see its content. A red dashed box has a gap at the chosen level.
